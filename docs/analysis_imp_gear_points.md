# Анализ: очки снаряжения вместо денег в магазине IMP

> travnik: анализ доработки, без изменений кода.
> Задача: наёмник получает фиксированный запас **очков экипировки**, каждая вещь
> стоит определённое число очков, очки ограничивают выбор. Деньги за снаряжение
> больше не списываются.

---

## 1. Как работает сейчас (деньги)

### Поток

```
IMP MainPage: клик по профилю
  └─ проверка LaptopSaveInfo.iCurrentBalance < iGetProfileCost( FALSE )
       └─ FALSE = только цена профиля, gear-стоимость ещё не известна

IMP Gear: выбор снаряжения
  └─ IMPGearDisplay(): gIMPGearCost = Σ (количество × цена предмета)   // каждый кадр

IMP Confirm: кнопка Finish
  └─ iIMPCost = iGetProfileCost( TRUE )
       = iIMPProfileCost + max( 0, gIMPGearCost - GetIMPShopGearBudget() )
  └─ проверка баланса
  └─ AddTransactionToPlayersBook( IMP_PROFILE, ..., -iIMPCost )

Загрузка готового IMP из <nick>.dat2 (LoadImpCharacter)
  └─ iIMPCost = iGetProfileCost( FALSE ) + max( 0, GetEquippedGearCost( profile ) - iIMPProfileCost )
```

### Суть текущей формулы

`IMP_PROFILE_COST` (по умолчанию 3000 $) — цена профиля, `IMP_SHOP_GEAR_BUDGET`
(по умолчанию 5000 $) — «бесплатная часть» снаряжения. На момент анализа это был
один параметр; после доработки бюджет вынесен отдельно. Игрок платит `max(цена профиля, стоимость снаряжения)`:
снаряжение в пределах 3000 $ бесплатно, всё сверх — доплачивается деньгами.
Динамическая цена (`DYNAMIC_IMP_PROFILE_COST`) умножает цену профиля на число IMP-слотов.

## 2. Целевая модель (очки)

### Основные сущности

| Сущность | Где живёт | Назначение |
|----------|-----------|-----------|
| `iIMPShopPoints` | `GameSettings` / `Ja2.ini` | Сколько очков у наёмника (например, 100) |
| `iIMPShopMoneyPerPoint` | `GameSettings` / `Ja2.ini` | Курс пересчёта цены в очки (fallback), например 32 $ = 1 очко |
| `usPoints` | `IMPShopItems.xml` (новая колонка) | Явная стоимость предмета в очках; `0` — считать по курсу |
| `gIMPGearPoints` | `IMP Gear.cpp` | Накопленные очки выбранного снаряжения (аналог `gIMPGearCost`) |
| `IMPShopAssortment::GetPoints( usItem )` | класс ассортимента | Очки предмета: XML-override или `ceil(price / курс)` |

### Правила

1. Очки **не сохраняются**: они вычисляются из выбранных предметов, как сейчас
   вычисляется стоимость. Формат сейва и `.dat2` не меняется, `SAVE_GAME_VERSION` остаётся 151.
2. Деньги за снаряжение не списываются вообще. При создании IMP платится только
   `iIMPProfileCost` (с учётом `DYNAMIC_IMP_PROFILE_COST`).
3. Ограничение — жёсткое: если сумма очков больше лимита, кнопка Finish недоступна
   (либо сообщение «Не хватает N очков»). Доплатить деньгами нельзя.
4. Стоимость в очках по умолчанию: `max(1, ceil(usPrice / iIMPShopMoneyPerPoint))`.
   Для предметов с ценой 0 — 1 очко (или явный 0 в XML для «бесплатных»).
5. `usPoints` в XML перекрывает формулу — это инструмент баланса (см. §3).

## 3. Стоимость предмета в очках

### Проблема: экономика модов разная

Цены в модах отличаются в 1.5–2 раза (AFS дороже 1.13/SDO). Один глобальный курс
даёт разный «размер бюджета» в разных модах.

Пример при курсе 30 $/очко и лимите 100 очков:

| Мод | Предмет | Цена | Очки |
|---|---|---:|---:|
| SDO | AK-47 | 1273 | 43 |
| SDO | Kevlar Vest | 800 | 27 |
| SDO | 1st Aid Kit | 100 | 4 |
| AFS | Beretta 92F | 1670 | 56 |
| AFS | MP5KA4 | 4150 | 139 |
| Data | SKS | 870 | 29 |

Типовой набор SDO (броня + винтовка + аптечка + LBE) ≈ 95–105 очков,
типовой набор AFS ≈ 130–140. То есть при одном курсе AFS «не влезает».

### Решение: явные очки в XML + fallback

* `IMPShopItems.xml` получает поле `<usPoints>` (UINT16).
* Наш генератор `docs/imp_kits/generate_imp_shop.py` считает очки **на мод** так,
  чтобы «эталонный набор» (броня + каска + основное оружие + LBE + аптечка)
  стоил ~80 очков из 100. Курс подбирается автоматически по эталонному набору мода.
* Для предметов, которых нет в XML (идут из `IMPItemChoices.xml`), работает
  глобальный fallback-курс из `Ja2.ini`.

Плюсы: баланс не зависит от инфляции цен мода; один и тот же лимит 100 очков
означает «примерно одинаковый набор» в любом моде. Минусы: очки надо
перегенерировать при изменении цен в `Items.xml`.

### Альтернативы (хуже)

| Вариант | Почему хуже |
|---------|-------------|
| Только глобальный курс | AFS и SDO требуют разного курса, один `Ja2.ini` на все конфиги |
| Очки = крутость | Теряется разница между дешёвой и дорогой вещью одной крутости |
| Очки = слоты (1 вещь = 1 очко) | Нет баланса: NVG и аптечка равны винтовке |
| Нормализация по медиане пула | Сложно объяснить, «прыгает» при правке XML |

## 6. Совместимость

| Сценарий | Поведение |
|----------|-----------|
| Старые сейвы | Работают: очки не хранятся, новых полей в структурах нет |
| Старые `.dat2` IMP-профили | Загружаются; доплата за снаряжение больше не начисляется |
| Новые IMP после доработки | Платят только цену профиля, снаряжение в пределах очков |
| Откат на старую версию | Сейвы совместимы; IMP сохраняет выданный инвентарь |
| Мультиплеер | Тот же путь `IMP Confirm`, отдельных изменений нет |

Риск: убрав доплату деньгами, мы уменьшаем денежный расход игрока на IMP
(было `max(3000, стоимость снаряжения)`, станет 3000). Компенсация — по желанию:
поднять `IMP_PROFILE_COST` или сделать очки зависимыми от цены профиля.

## 7. Баланс: что учесть

1. **Лимит очков** — 100 по умолчанию (паритет с 3000 $ при курсе 30 $/очко).
2. **Цена профиля** (`IMP_PROFILE_COST`) остаётся денежной и не меняется.
   В документации нужно перестать называть её «бесплатной частью снаряжения».
3. **Дорогие модели** (AFS) при явных очках в XML становятся «набор без брони» —
   это осознанный выбор игрока, а не запрет.
4. **NVG/отмычки/камуфляж** уже привязаны к трейтам в `IMPShopItems.xml` —
   очки не ломают эту привязку.
5. **`ubMaxAmount`** продолжает ограничивать копии; очки считаются с тем же
   ограничением (иначе можно набрать 3 аптечки и заплатить за 2).
6. **Динамическая цена профиля** (`DYNAMIC_IMP_PROFILE_COST`) не влияет на очки,
   но влияет на деньги — проверить, что это ожидаемое поведение.

## 8. Этапы внедрения

| Этап | Что делаем | Результат |
|:--:|---|---|
| 1 | Настройки + `GetPoints()` с fallback-курсом, очки только отображаются | Видно `Очки: N / 100`, деньги считаются как раньше |
| 2 | Переключение оплаты: `iGetProfileCost()` без gear, блокировка Finish | Очки реально ограничивают выбор |
| 3 | `<usPoints>` в XML + генератор, перегенерация 4 модов | Баланс одинаковый во всех модах |
| 4 | Локализация, подсказки, сортировка пула по очкам | Готовый UX |
| 5 | Опциональный `IMP_SHOP_USE_POINTS` (0 = старая денежная схема) | Безопасный откат и совместимость с чужими сборками |

Оценка: **2–3 рабочих дня** (без этапа 5 — ~2 дня).

## 9. Риски и подводные камни

* `gIMPGearCost` пересчитывается **каждый кадр** в `IMPGearDisplay` — очки нужно
  считать там же, иначе рассинхрон с `ubMaxAmount`.
* Заблокированная кнопка Finish должна перерисовываться при изменении выбора
  (сейчас кнопка создаётся один раз в `EnterIMPGear`).
* Предметы с ценой 0 и предметы вне XML — нужен предсказуемый минимум (1 очко).
* `GetEquippedGearCost` после доработки остаётся нужен только для отладки/легаси;
  не удалять, чтобы не ломать `.dat2`-совместимость.
* Строки `szIMPGearWebSiteText` индексируются по номеру: добавление `[8]`/`[9]`
  требует правки **всех** 8 языковых файлов, иначе в не-русских будет мусор.
* Если оставить денежную доплату как опцию, нельзя одновременно показывать
  «очки» и «деньги» без явного разделения — игрок запутается.
* `IMP MainPage` проверяет баланс только по цене профиля — при очках это корректно,
  но при этапе 1 (очки только отображаются) деньги всё ещё могут не хватить на
  этапе Finish — порядок этапов важен.

## 10. Открытые вопросы

1. **Лимит очков**: фиксированный (100) или зависит от сложности/бэкграунда/уровня?
2. **Строгость**: жёсткий лимит или разрешить превышение за деньги (гибрид)?
3. **Обратная совместимость**: нужен ли `IMP_SHOP_USE_POINTS` для отката?
4. **Очки в XML**: делаем явные очки на мод (рекомендуется) или только глобальный курс?
5. **Старые IMP**: при загрузке `.dat2` доплату убираем полностью — подтверждаем?
6. **Компенсация денег**: поднимать `IMP_PROFILE_COST` или оставить как есть?
7. Показывать ли в подсказке денежный эквивалент очков (для наглядности)?
