# Внешний ассортимент магазина IMP (IMPShopItems.xml)

> travnik: необязательный XML-файл, который дополняет ассортимент страницы
> выбора снаряжения IMP (`Laptop\IMP Gear.cpp`).

---

## Назначение

Базовый пул предметов магазина собирается из `IMPItemChoices.xml` по категориям
(базовые категории + категории выбранных трейтов). Этого мало: нельзя добавить
предмет, которого нет ни в одной категории, нельзя изменить его цену, крутость
или привязать к конкретному набору, нельзя убрать лишнее.

`IMPShopItems.xml` решает эти задачи, **не заменяя** `IMPItemChoices.xml`:

* добавляет любые предметы в пул магазина;
* переопределяет цену (влияет и на доплату за снаряжение);
* переопределяет крутость (в том числе «разрешает» предметы с `ubCoolness = 0`,
  которые `ItemIsLegal()` обычно не пропускает);
* привязывает предмет к набору/трейту;
* ограничивает количество копий;
* исключает предмет из ассортимента.

Если файла нет — магазин работает ровно как раньше.

## Расположение файла

### В репозитории (источник)

```
<repo>\GameDirectory\<папка мода>\TableData\Inventory\IMPShopItems.xml
```

Файлы лежат в `GameDirectory` и версионируются вместе с модом:

| Файл | Конфигурация |
|------|--------------|
| `GameDirectory\Data\TableData\Inventory\IMPShopItems.xml` | vanilla |
| `GameDirectory\Data-1.13\TableData\Inventory\IMPShopItems.xml` | 113 |
| `GameDirectory\Data-AFS\TableData\Inventory\IMPShopItems.xml` | AR+AFS |
| `GameDirectory\Data-SDO\TableData\Inventory\IMPShopItems.xml` | AR+SDO, SDO |

### В игре (рабочая копия)

При деплое содержимое `GameDirectory` копируется в папку игры, и файл оказывается по пути:

```
<папка игры>\<папка мода>\TableData\Inventory\IMPShopItems.xml
```

VFS читает **один** файл по этому пути — из профиля с наибольшим приоритетом.
Загрузка выполняется в `LoadExternalGameplayData()` (`Init.cpp`) сразу после
`IMPItemChoices.xml`:

```cpp
strcpy(fileName, directoryName);
strcat(fileName, IMPSHOPITEMSXMLFILENAME);
if (FileExists(fileName))
{
    IMPShopAssortment::Instance().Load(fileName);
}
```

Отсутствие файла и ошибки разбора не прерывают запуск игры.

## Формат файла

```xml
<?xml version="1.0" encoding="utf-8"?>
<IMPSHOPITEMS>
    <fRespectCoolness>0</fRespectCoolness>

    <IMPSHOPITEM>
        <uiIndex>1</uiIndex>
        <usItem>201</usItem>
        <usPrice>50</usPrice>
        <ubCoolness>0</ubCoolness>
        <ubKit>255</ubKit>
        <ubMaxAmount>2</ubMaxAmount>
        <fForceAvailable>0</fForceAvailable>
        <fRemove>0</fRemove>
        <szComment>Example: discounted 1st Aid Kit, max 2</szComment>
    </IMPSHOPITEM>
</IMPSHOPITEMS>
```

### Корневое поле

| Поле | По умолчанию | Назначение |
|------|:---:|-----------|
| `fRespectCoolness` | 0 | 0 — крутость из XML ни на что не влияет; 1 — предмет с заданной крутостью появляется в магазине только при достижении прогресса кампании `ubCoolness * 10` процентов |

### Поля записи `IMPSHOPITEM`

| Поле | Обяз. | Назначение |
|------|:---:|-----------|
| `uiIndex` | нет | Номер записи для сообщений в лог. На логику не влияет |
| `usItem` | **да** | `uiIndex` предмета из `Items.xml`. Запись без предмета игнорируется |
| `usPrice` | нет | Цена в магазине IMP. `0` — взять `usPrice` из `Items.xml` |
| `ubCoolness` | нет | Крутость в магазине IMP. `0` — взять `ubCoolness` из `Items.xml`. Если задана (`> 0`), предмет считается допустимым даже при нулевой крутости в `Items.xml` |
| `ubKit` | нет | `uiIndex` категории из `IMPItemChoices.xml`. `255` — без привязки, предмет доступен всегда |
| `ubMaxAmount` | нет | Максимум копий предмета в снаряжении. `0` — без ограничения |
| `fForceAvailable` | нет | `1` — добавлять предмет, даже если его запрещает `ItemIsLegal()` (Sci-Fi при обычном стиле, предметы другой системы инвентаря и т.п.) |
| `fRemove` | нет | `1` — убрать предмет из ассортимента, даже если он пришёл из `IMPItemChoices.xml` |
| `szComment` | нет | Произвольный текст для читателя файла, игрой не используется |

## Правила применения

`IMPShopAssortment::ApplyToPool( pool, activeKits )` вызывается в конце
`CalculatePossibleItems()` и обрабатывает записи в таком порядке:

1. `fRemove = 1` — предмет удаляется из пула и больше не обрабатывается.
2. `ubKit != 255` и категории нет среди активных — запись пропускается.
   Активные категории собирает сам `AddItemCategoryToPossibleGear()`, поэтому
   наборы 0–11 (Default, Random, характеристики) активны всегда, а трейтовые —
   только при выбранном трейте.
3. Проверка допустимости: `usItem` существует, класс предмета не 0, затем
   `ItemIsLegal( usItem, ubCoolness > 0 )`. Оружие разрешается всегда,
   остальное — при `fForceAvailable = 1`.
4. Проверка крутости (только при `fRespectCoolness = 1` и заданной `ubCoolness`).
5. Предмет добавляется в `std::set` пула; распределение по слотам инвентаря
   остаётся штатным — по классу предмета в `DistributePossibleItemsToVectors()`.

Повтор `usItem` в файле: применяется последняя запись.

## Влияние на стоимость

Цена из XML используется везде, где считается стоимость снаряжения:

| Место | Что делает |
|-------|-----------|
| `IMPGearDisplay()` | Начисляет `gIMPGearCost` при отрисовке выбранного снаряжения (с учётом `ubMaxAmount`) |
| `GetEquippedGearCost()` (`IMP Confirm.cpp`) | Пересчитывает стоимость уже выданного снаряжения при найме/загрузке IMP |

Поэтому переопределённая цена одинаково влияет и на доплату при создании IMP,
и на последующий расчёт стоимости профиля. Если `ubMaxAmount` ограничивает
количество, лишние копии не оплачиваются и не выдаются.

Доплата считается от отдельного бюджета снаряжения `IMP_SHOP_GEAR_BUDGET`
(по умолчанию 5000 $; `0` — использовать `IMP_PROFILE_COST`):

* `GetIMPGearCost() = max(0, стоимость снаряжения - бюджет)`;
* на экране выбора постоянно видно `Снаряжение: N / M $   Доплата: K $`;
* при `K > 0` кнопка Finish сначала показывает подтверждение с итоговой суммой.

## Подсказка в интерфейсе

При наведении на предмет в пуле магазина под описанием выводится строка
`Цена: %d$  Крутость: %d` (`szIMPGearWebSiteText[7]`). Показывается фактическая
цена и крутость с учётом переопределений из XML.

## Ограничения

* `usPrice = 0` означает «взять из `Items.xml`»; сделать предмет бесплатным
  через XML нельзя, для этого цена правится в `Items.xml`.
* Файл только дополняет и точечно исключает предметы; «заменить весь пул»
  нельзя (для этого достаточно `fRemove` на нужных предметах).
* Список не сохраняется в профиль IMP: в сейв попадает уже выданный инвентарь.
  Это осознанное решение: формат профиля и сейва не меняется, `SAVE_GAME_VERSION`
  остаётся 151, новые поля в `MERCPROFILESTRUCT` не добавляются. При необходимости
  набор восстанавливается из `inv[]` (предмет → количество), а стоимость — через
  `GetEquippedGearCost()`.
* Цена и крутость из XML не меняют `Item[]` — другие механики (магазины,
  дропы, Бобби Рэй) продолжают использовать значения из `Items.xml`.

## Готовый ассортимент по модам

Файлы `IMPShopItems.xml` созданы для каждой папки мода, у которой есть свой `Items.xml`,
и заполнены повседневным снаряжением (не endgame) с крутостью 1–4:

| Папка | Записей | Цены, $ | Особенности |
|-------|--------:|---------|-------------|
| `Data` | 35 | 50–1602 | ванильная база: без LBE (старая система инвентаря) |
| `Data-1.13` | 49 | 50–1760 | пистолеты/ПП/винтовки, броня, LBE, медицина |
| `Data-AFS` | 43 | 50–4150 | локальные AFS-модели (Glock 17 Gen1, Ingram M11 и т.п.) |
| `Data-SDO` | 57 | 40–1500 | самый полный набор: 9 видов брони, LBE, камуфляж |

Правила, по которым подобрано снаряжение (и по которым стоит править файл дальше):

* `ubCoolness` — реальное значение из `Items.xml`, но не выше 4; предметы с крутостью 0
  (не продаются) и endgame-снаряжение не добавлены;
* `usPrice = 0` — цена берётся из `Items.xml`, скидок и наценок нет;
* `fForceAvailable = 0` — штатные фильтры `ItemIsLegal` продолжают работать
  (Tons of Guns, Sci-Fi, система инвентаря и т.п.);
* `ubMaxAmount`: броня, разгрузка и оружие — 1, медицина и граны — 2;
* `ubKit`: NVG — только Night Ops (24), отмычки — Lockpicking (31),
  камуфляжные наборы — Camouflage (33), рация — Vox Operator (51), остальное — 255 (всем);
* патроны не добавлены: магазины подставляются автоматически при выборе оружия.

### Приоритет файлов (VFS)

VFS подхватывает **один** файл по пути `TableData\Inventory\IMPShopItems.xml` —
из профиля с наибольшим приоритетом. Поэтому:

* файл лежит в папке каждого мода и подхватывается своей конфигурацией
  (`Data` → vanilla, `Data-1.13` → 113, `Data-SDO` → AR+SDO и SDO, `Data-AFS` → AR+AFS);
* в `Data-User` файла нет — иначе он перекрыл бы ассортимент всех модов сразу;
* моды-архивы (`Data-AR*.7z`, `Data-WF*.7z`, `Data-SDO-ru.7z` и т.п.) свой
  `Items.xml` не содержат, поэтому им достаётся файл базовой папки;
  исключение — `Data-DL113.7z`: у него свой `Items.xml` внутри архива, для него
  файл нужно добавлять в архив или в `Data-User`.

## Генерация файла

Файлы `IMPShopItems.xml` не правятся вручную: их создаёт скрипт
`docs/imp_kits/generate_imp_shop.py`. Нужен Python 3, сторонние библиотеки
не требуются.

### Запуск

Из корня репозитория:

```
python docs/imp_kits/generate_imp_shop.py --game-root D:\Projects\JA2_Game
```

`--game-root` — папка игры, откуда читаются `Items.xml` и `IMPItemChoices.xml`
(по умолчанию `D:\Projects\JA2_Game`).

`--out-root` — куда писать готовые файлы; по умолчанию `<repo>\GameDirectory`.
Именно эта папка версионируется, после генерации её содержимое копируется в игру.

Пример вывода:

```
Data -> D:\Projects\JA2_Game\Data\TableData\Inventory\IMPShopItems.xml (35 записей)
Data-1.13 -> ... (49 записей)
Data-AFS -> ... (43 записей)
Data-SDO -> ... (57 записей)
```

### Что делает скрипт

1. Читает `TableData\Items\Items.xml` и `TableData\Inventory\IMPItemChoices.xml`
   выбранного мода.
2. Для каждой записи проверяет:
   * предмет существует в `Items.xml`;
   * его `ubCoolness` в диапазоне 1–4 (жёсткая проверка баланса);
   * при `ubKit != 255` такая категория есть в `IMPItemChoices.xml`.
3. Если проверки не прошли, файл этого мода **не перезаписывается**, а ошибки
   выводятся в консоль.
4. Записывает `<out-root>\<мод>\TableData\Inventory\IMPShopItems.xml`
   (по умолчанию `GameDirectory`) в UTF-8 с CRLF.
   Цена в очках/деньгах не фиксируется: `usPrice = 0`, всё берётся из `Items.xml`.

### Как править ассортимент

Все списки лежат в таблице `MODS` в начале скрипта:

```python
"Data-SDO": {
    "title": "SDO (Data-SDO)",
    "groups": [
        ("Пистолеты и револьверы", [e(1), e(3), e(8), e(631), ...]),
        ...
    ],
},
```

* `e(<id>)` — предмет, 1 копия, доступен всем;
* `e(<id>, 2)` — не больше двух копий;
* `e(<id>, 1, KIT_NIGHT_OPS)` — только с набором Night Ops (24).

Доступные константы наборов: `KIT_NIGHT_OPS` (24), `KIT_LOCKPICKING` (31),
`KIT_CAMOUFLAGE` (33), `KIT_RADIO_OPERATOR` (51), `KIT_ALWAYS` (255).

После правки — перезапустить скрипт. Цены читаются из `Items.xml` во время
игры, поэтому менять их в XML не нужно; а вот крутость фиксируется в файле
при генерации — если правили `ubCoolness` в `Items.xml`, скрипт нужно
перезапустить.

### Добавление нового мода

1. Добавить в `MODS` новую секцию с ключом — именем папки мода.
2. Убедиться, что в папке есть `TableData\Items\Items.xml` и
   `TableData\Inventory\IMPItemChoices.xml`.
3. Заполнить группы записями `e(...)`.
4. Запустить скрипт: он создаст `IMPShopItems.xml` в папке этого мода.

Для модов-архивов (`.7z`) скрипт не подходит напрямую: файл нужно добавить
внутрь архива или положить в `Data-User` (тогда он перекроет все моды).
