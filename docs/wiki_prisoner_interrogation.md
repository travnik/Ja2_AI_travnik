# Допрос военнопленных

> travnik: механика плена и допроса — от захвата пленных до накопления
> очков допроса, обработки результатов, охраны тюрьмы и работы снаitch-ей.

---

## Назначение

Система плена позволяет брать солдат противника в плен, содержать их в
тюрьме и допрашивать. Успешный допрос может дать:

- переход пленного на нашу сторону в качестве ополченца;
- сведения о передвижении вражеских групп;
- денежный выкуп;
- освобождение пленного без выгоды.

Допрос работает только на стратегической карте и только в наземных секторах.
Подземных тюрем нет.

---

## 1. Военнопленные

### Типы пленных

В `Strategic\Campaign Types.h` определены четыре типа:

| Тип | Константа | Ценность для бунта |
|---|---|---:|
| Администратор | `PRISONER_ADMIN` | 75 |
| Регулярный солдат | `PRISONER_REGULAR` | 100 |
| Элитный солдат | `PRISONER_ELITE` | 125 |
| Офицер | `PRISONER_OFFICER` | 200 |

Количество пленных по типам хранится в `SECTORINFO`:

```cpp
UINT8 uiNumberOfPrisonersOfWar[PRISONER_MAX];
```

### Как пленные попадают в тюрьму

Пленные появляются при сдаче вражеских солдат. За это отвечают настройки:

- `ALLOW_TAKE_PRISONERS` — разрешает систему плена;
- `ENEMY_CAN_SURRENDER` — разрешает врагу сдаваться;
- `PLAYER_CAN_ASK_TO_SURRENDER` — разрешает игроку требовать сдачи;
- `SURRENDER_MULTIPLIER` — общий множитель готовности к сдаче.

После боя игрок выбирает тюрьму, куда отправить пленных. Список доступных
тюрем формирует `GetPlayerControlledPrisonList()` (`Tactical\Overhead.cpp`):
сектор должен быть под контролем игрока, без врагов и с тюремным facility.
Если подходящей тюрьмы нет, игра сообщает об этом; пленные не попадают в тюрьму, а часть из них может вернуться к королеве.

В тактическом секторе пленные отображаются как гражданские с флагом
`SOLDIER_POW_PRISON` и группой `POW_PRISON_CIV_GROUP`, но стратегическая
механика работает с их количеством в `SECTORINFO`, а не с отдельными
солдатами.

## 2. Тюрьма

Тюрьмой считается facility, у которого в assignment
`FAC_INTERROGATE_PRISONERS` задано:

```xml
<usPrisonBaseLimit>...</usPrisonBaseLimit>
```

Это поле одновременно:

- определяет, что facility является тюрьмой;
- задаёт безопасный лимит пленных: если пленных больше, возможен бунт.

Также используются:

| Параметр facility | Назначение |
|---|---|
| `ubStaffLimit` | максимальное число бойцов на assignment |
| `usPerformance` | эффективность тюрьмы, `100` — обычная |
| `usPrisonBaseLimit` | безопасный лимит пленных и признак тюрьмы |

Для снаitch-ей используется отдельное assignment `FAC_PRISON_SNITCH`
со своими `ubStaffLimit` и `usPerformance`.

## 3. Кто даёт очки допроса

Очки допроса начисляются раз в час в `UpdateAssignments()`
(`Strategic\Hourly Update.cpp`), которая вызывает
`HandlePrisonerProcessingInSector()` (`Strategic\Assignments.cpp`).

Для начисления очков нужны:

1. тюрьма в секторе;
2. пленные в тюрьме;
3. наземный сектор (`bZ == 0`);
4. сектор принадлежит игроку и в нём нет боя;
5. хотя бы один подходящий допрашивающий.

### Обычный допрашивающий

Боец должен:

- быть на assignment `FACILITY_INTERROGATE_PRISONERS`;
- не спать;
- провести на assignment не меньше
  `MINUTES_FOR_ASSIGNMENT_TO_COUNT` минут (по умолчанию 45).

Проверка выполняется в `EnoughTimeOnAssignment()`.

### Снаitch

Снаitch должен:

- иметь трейт `SNITCH_NT`;
- быть живым и в сознании;
- находиться на поверхности;
- не быть в пути или между секторами;
- не быть EPC;
- проходить `CanCharacterSnitchInPrison()`:
  - в секторе нет врагов;
  - бойца не знают как наёмника в этом секторе;
  - в секторе есть тюрьма с пленными;
- быть на assignment `FACILITY_PRISON_SNITCH`;
- не спать;
- провести на assignment не меньше 45 минут;
- не быть раскрытым в этот час.

## 4. Накопление очков

### Хранение остатка

Очки хранятся в `SECTORINFO`:

```cpp
UINT8 uiInterrogationHundredsLeft;
```

Несмотря на название, поле хранит **остаток 0–99**, а не сотни. После
распределения очков сохраняется только младшая часть:

```cpp
UINT32 losthundreds = interrogationpoints / 100;
pSectorInfo->uiInterrogationHundredsLeft =
    (UINT8)(interrogationpoints - losthundreds * 100);
```

Всё, что выше 99 и не было потрачено, отбрасывается. При стандартных порогах
80–100 это почти не заметно, но при больших порогах из INI или при отсутствии
подходящих пленных можно потерять накопленные сотни.

### Формула обычного допрашивающего

`CalculateInterrogationValue()`:

```text
база = 50 + 10 * EffectiveExpLevel + EffectiveLeadership

угроза = CalcThreateningEffectiveness()
угроза = угроза * usApproachFactor[2]
угроза = угроза * (100 + BG_PERC_APPROACH_THREATEN) / 100

очки = база * угроза
очки = очки * (100 + BG_PERC_INTERROGATION) / 100
очки = очки * performance / 650000
очки = очки - очки * штраф_за_усталость / 100
```

Где:

- `CalcThreateningEffectiveness()` — среднее из лидерства, силы и
  смертоносности оружия в основной руке;
- `usApproachFactor[2]` — множитель подхода «угроза» из профиля;
- `BG_PERC_APPROACH_THREATEN` и `BG_PERC_INTERROGATION` — бонусы бэкграунда;
- `performance` — `usPerformance` тюрьмы, ограниченный диапазоном 10–1000.

Оружие влияет только через `ubDeadliness` предмета в `HANDPOS`. Если в руке
нет оружия или у оружия `ubDeadliness = 0`, применяется штраф `-30`.

### Формула снаitch-а

`CalculateSnitchInterrogationValue()`:

```text
база = 50
     + 10 * EffectiveExpLevel
     + EffectiveLeadership
     + EffectiveWisdom

если новая система трейтов:
    база += 10 * уровень Covert

дружелюбие = ((EffectiveLeadership + EffectiveWisdom) / 2)
           * usApproachFactor[0]

если характер ASSERTIVE:
    дружелюбие += 30

дружелюбие = дружелюбие * (100 + BG_PERC_APPROACH_FRIENDLY) / 100

очки = база * дружелюбие
performance = usPerformance * PRISON_SNITCH_INTERROGATION_MULTIPLIER
performance = clamp(performance, 10, 1000)
очки = очки * performance / 650000
очки = очки - очки * штраф_за_усталость / 100
```

`PRISON_SNITCH_INTERROGATION_MULTIPLIER` задаётся в секции `[Snitch]`
файла `Ja2_Options.ini`, по умолчанию `3.0`.

### Штраф за усталость

`ReducePointsForFatigue()` (`Tactical\SkillCheck.cpp`) использует
`bBreathMax`:

| `bBreathMax` | Штраф |
|---:|---:|
| 85+ | 0 % |
| 70–84 | 10 % |
| 50–69 | 25 % |
| 30–49 | 50 % |
| 15–29 | 75 % |
| 1–14 | 90 % |
| 0 | 100 % |

### Пример

Двое допрашивающих дали 55 и 40 очков, с прошлого часа осталось 10:

```text
10 + 55 + 40 = 105 очков
```

Порог администратора — 80. Обрабатывается один администратор:

```text
105 - 80 = 25 очков
```

Остаток 25 сохраняется на следующий час.

## 5. Расход очков и обработка пленных

### Пороги допроса

Пороги задаются в `Ja2_Options.ini`, секция
`[Strategic Gameplay Settings]`:

```ini
; Очки, необходимые для допроса администратора
PRISONER_INTERROGATION_POINTS_ADMIN = 80

; Очки, необходимые для допроса регулярного солдата
PRISONER_INTERROGATION_POINTS_REGULAR = 100

; Очки, необходимые для допроса элитного солдата
PRISONER_INTERROGATION_POINTS_ELITE = 100

; Очки, необходимые для допроса офицера
PRISONER_INTERROGATION_POINTS_OFFICER = 100
```

Каждый следующий порог не может быть меньше предыдущего.

### Порядок обработки

Пленные допрашиваются в порядке:

1. администраторы;
2. регулярные;
3. элита;
4. офицеры.

Для каждого типа:

```cpp
while ( prisoners[i] > 0
     && interrogationpoints >= PRISONER_INTERROGATION_POINTS[i] )
{
    interrogationpoints -= PRISONER_INTERROGATION_POINTS[i];
    --prisoners[i];
    ++interrogatedprisoners[i];
}
```

### Исход допроса

Для каждого обработанного пленного выполняется бросок:

```cpp
UINT8 result = Random(100);
```

Далее:

```text
result < PRISONER_DEFECT_CHANCE
    -> переход на нашу сторону

result < PRISONER_DEFECT_CHANCE + PRISONER_INFO_BASECHANCE
    -> сведения о враге

result < PRISONER_DEFECT_CHANCE
       + PRISONER_INFO_BASECHANCE
       + PRISONER_RANSOM_CHANCE
    -> выкуп

иначе
    -> освобождение без выгоды
```

При значениях по умолчанию:

| Исход | Шанс |
|---|---:|
| Переход в ополчение | 25 % |
| Сведения | 25 % |
| Выкуп | 25 % |
| Освобождение | 25 % |

Если сумма настроек превышает 100, часть исходов может стать недостижимой,
потому что проверки идут последовательно.

### Переход в ополчение

При исходе «переход» пленный может быть понижен:

- офицер с шансом 80 % остаётся офицером;
- элита с шансом 80 % остаётся элитой;
- регулярный с шансом 80 % остаётся регулярным;
- иначе пленный становится администратором.

Полученное ополчение добавляется в сектор:

- администраторы → зелёная милиция;
- регулярные → регулярная милиция;
- элита и офицеры → элитная милиция.

В текущей реализации из-за последовательных `if` один пленный может быть
добавлен более чем в одну категорию ополчения. Это особенность существующего
кода, а не задуманная механика.

### Сведения о враге

При исходе «сведения» выполняется до 20 попыток найти сектор:

- с мобильными врагами;
- о котором игрок ещё не знает.

При успехе выставляются флаги:

- `SF_ASSIGN_NOTICED_ENEMIES_HERE` — обнаружены враги;
- `SF_ASSIGN_NOTICED_ENEMIES_KNOW_NUMBER` — известно количество;
- `SF_ASSIGN_NOTICED_ENEMIES_KNOW_DIRECTION` — известно направление.

Шансы на количество и направление задаются отдельно:

- `PRISONER_INFO_NUMBER_CHANCE`;
- `PRISONER_INFO_DIRECTION_CHANCE`.

### Выкуп

Сумма выкупа зависит от типа пленного и прогресса игры:

```text
выкуп = round( БАЗА[тип] * (1 + K * P / 100) )
```

Где:

- `БАЗА[тип]` — `PRISONER_RANSOM_MONEY_*`;
- `K` — `PRISONER_RANSOM_PROGRESS_COEFFICIENT`;
- `P` — текущий прогресс игры, 0–100 %.

Подробнее — в отдельной странице `wiki_prisoner_ransom.md`.

### Возврат к королеве

После исходов «сведения», «выкуп» и «освобождение» есть шанс, что пленный
вернётся к королеве и увеличит пул подкреплений:

```cpp
if ( Random(100) < PRISONER_RETURN_TO_ARMY_CHANCE
     && !gfUnlimitedTroops )
    ++giReinforcementPool;
```

При исходе «переход в ополчение» проверка возврата пропускается.

### Опыт допрашивающих

После удаления допрошенных пленных допрашивающие получают опыт:

```text
totalexp = количество допрошенных
expratio = totalexp / (oldinterrogationpoints * 33)
exppoints = expratio * CalculateInterrogationValue(боец)
```

Затем:

```text
Лидерство += exppoints
Мудрость  += max(0, exppoints - 1)
Опыт      += max(0, exppoints - 2)
```

`oldinterrogationpoints` — это остаток очков, перенесённый с прошлого часа,
а не все очки, накопленные за текущий час. Если остаток был нулевым, опыт
не начисляется.

## 6. Охрана тюрьмы

### Сила обычного охранника

`CalculatePrisonGuardValue()`:

```text
value = 15 * EffectiveExpLevel
      + EffectiveLeadership / 2
      + 2 * EffectiveStrength
```

Бонусы новой системы трейтов:

```text
value += 25 * уровень Martial Arts
value += 10, если есть Melee
```

Бонусы старой системы трейтов:

```text
value += 25 * уровень Martial Arts
value += 25 * уровень Hand-to-Hand
value += 10, если есть Knifing
```

Затем:

```text
value = value * (100 + max(0, BG_PERC_GUARD)) / 100
value = value - value * штраф_за_усталость / 100
```

Охранником считается любой боец в секторе, кроме снаitch-а на assignment
`FACILITY_PRISON_SNITCH`.

### Милиция

```text
value += 100 * зелёная милиция
value += 150 * регулярная милиция
value += 200 * элитная милиция
```

В подсчёте количества охранников каждый милиционер даёт `+1` независимо
от уровня.

### Сила снаitch-а как охранника

`CalculateSnitchGuardValue()`:

```text
value = 15 * EffectiveExpLevel
      + EffectiveLeadership / 2
      + 2 * EffectiveWisdom

новая система:
    value += 25 * уровень Covert
    value += 10 * уровень Stealthy

старая система:
    value += 25 * уровень Stealthy

если боец глухой:
    value = value / 2

value = value - value * штраф_за_усталость / 100
```

Снаitch-и добавляют силу охраны только если есть хотя бы один обычный
охранник.

## 7. Риск бунта

Бунт проверяется раз в час в `HandlePrison()`.

### Сила пленных

```text
prisonerriotvalue =
      200 * офицеры
    + 125 * элита
    + 100 * регулярные
    +  75 * администраторы
```

### Условия бунта

```cpp
if ( numprisonguards == 0 )
    fBeginRiot = TRUE;
else if ( prisonerriotvalue > prisonguardvalue
       && numprisoners > prisonerbaselimit
       && Random(prisonerriotvalue) > Random(prisonguardvalue) )
    fBeginRiot = TRUE;
```

То есть:

1. если обычных охранников нет — бунт сразу;
2. иначе бунт возможен только если:
   - сила пленных больше силы охраны;
   - пленных больше `usPrisonBaseLimit`;
   - случайный бросок пленных больше случайного броска охраны.

Если пленных не больше базового лимита тюрьмы, случайного бунта не будет.

### Вероятность

При `A = prisonerriotvalue` и `B = prisonguardvalue`, `A > B > 0`:

```text
P(бунт) ≈ (2A - B - 1) / (2A)
```

Если `B = 0`, `Random(0)` всегда возвращает `0`, и бунт практически
гарантирован.

### Сколько пленных сбегает

При бунте:

```text
ratio = prisonerriotvalue / prisonguardvalue
```

Если охраны нет, `ratio = 1.0`.

Для каждого типа:

```text
escaped = min( Random(1 + (UINT8)(количество * ratio)),
               количество )
```

Сбежавшие добавляются врагу:

- регулярные → `ubNumTroops`;
- элита и офицеры → `ubNumElites`;
- администраторы → `ubNumAdmins`.

### Особенности охраны и бунта

- **Спящие бойцы учитываются в силе охраны, но не в количестве.**
  `CalculateAllGuardsValueInPrison()` не проверяет сон, а
  `CalculateAllGuardsNumberInPrison()` проверяет. Если все обычные бойцы
  спят и милиции нет, количество охранников будет `0` — это автоматический
  бунт.

- **Милиция может учитываться дважды.**
  `CalculateAllGuardsValueInPrison()` добавляет силу милиции. Затем, если
  есть обычные охранники, вызывается `CalculateAllSnitchesGuardValueInPrison()`,
  которая снова добавляет ту же силу милиции.

- **Снаitch-и не заменяют обычных охранников.**
  Если есть только снаitch-и, `numprisonguards == 0`, и бунт начинается
  автоматически.

## 8. Снаitch-и

### Раскрытие

Перед начислением очков допроса вызывается `HandleSnitchExposition()`.

Подозрение:

```text
suspicion = 10 + количество элиты + количество офицеров
```

Качество прикрытия:

```text
cover = (10 * EffectiveExpLevel
       + 2 * EffectiveLeadership
       + EffectiveWisdom) / 4

новая система:
    cover += 25 * уровень Covert
    cover += 10, если есть Stealthy

старая система:
    cover += 10, если есть Stealthy
```

Проверка:

```cpp
if ( Random(suspicion) > Random(cover) )
    // снаitch раскрыт
```

Если снаitch раскрыт:

- его помечают как известного наёмника в этом секторе;
- в этот час он не даёт очки допроса;
- далее возможны варианты: он замечает раскрытие, убалтывает охрану,
  избегает засады, охрана предотвращает нападение — либо пленные нападают
  на него (утопление, избиение, нож, удушение), что может закончиться
  ранением или смертью.

### Оружие снаitch-а

Оружие в руках снаitch-а не влияет ни на его очки допроса, ни на силу
охраны. Формулы снаitch-а не используют `CalcThreateningEffectiveness()`.

## 11. Сохранение и загрузка

Уже применённый результат допроса сохраняется:

- количество пленных хранится в `SECTORINFO`;
- остаток очков хранится в `SECTORINFO`;
- выкуп проводится по финансовой книге;
- `SECTORINFO` пишется в сейв целиком.

Случайный исход допроса защищён настройкой:

```ini
; Защита результата допроса от повторного броска после Save/Load
PRISONER_INTERROGATION_SAVELOAD_PROTECTION = TRUE
```

По умолчанию защита включена.

Когда защита включена, для допроса используется локальный детерминированный
ГПСЧ. Seed строится из состояния, которое уже сохраняется в сейве:

- номер сектора;
- номер игрового часа;
- накопленные очки допроса;
- остаток очков с прошлого часа;
- количество пленных каждого типа.

Для проверки раскрытия снаitch-а seed дополнительно учитывает ID бойца и
количество пленных.

Поэтому сохранение перед часовой обработкой и загрузка дают тот же результат:
те же пленные, тот же исход, та же сумма выкупа. При этом разные сектора,
часы и состояния тюрьмы дают разные последовательности.

Если настройка выключена (`FALSE`), используется прежний глобальный
`Random()` / `PreRandom()`, и после Save/Load исход может измениться.

Защита фиксирует результат для **одинакового состояния игры**. Если между
сохранением и обработкой игрок изменил количество пленных, очки допроса,
состав допрашивающих или настройки, результат может отличаться — это уже
другое состояние.
## 12. Известные особенности

- Допрос работает только на поверхности.
- Если в секторе нет активных допрашивающих, новые очки не начисляются,
  а остаток с прошлого часа может быть потерян.
- Если сектор перестал быть «наш и мирный», остаток очков также теряется.
- В `uiInterrogationHundredsLeft` сохраняется только остаток `0–99`;
  всё, что выше, отбрасывается.
- Спящие охранники дают силу охраны, но не считаются в количестве охранников.
- При наличии обычных охранников сила милиции может учитываться дважды.
- При переходе в ополчение текущая логика может добавить одного пленного
  более чем в одну категорию.
- Опыт допрашивающих начисляется только при ненулевом остатке очков
  с прошлого часа.
