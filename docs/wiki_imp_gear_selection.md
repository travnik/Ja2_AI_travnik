# Выбор снаряжения IMP (IMP Gear Selection)

> Порт фичи из основного репозитория JA2 1.13 (`1dot13/source`, автор Flugente).
> Позволяет игроку вручную выбрать стартовое снаряжение создаваемого IMP-наёмника
> вместо случайной выдачи по ответам анкеты.

---

## Игровое описание

После экрана распределения атрибутов появляется страница **«Как будет
выбираться снаряжение?»** с двумя кнопками:

- **Автоматически** (старый метод) — снаряжение выдаётся случайно согласно
  ответам анкеты, как в оригинале. Дополнение: IMP всегда получает пистолет
  из категории `Sidearm` (`IMPItemChoices.xml`, uiIndex 52), поэтому не может
  остаться без оружия.
- **Вручную** (новый метод) — экран выбора снаряжения: ~27 выпадающих списков,
  по одному на каждый слот снаряжения. Для каждого слота кнопками **+/−**
  задаётся количество предметов.

### Слоты выбора

| Группа | Слоты |
|--------|-------|
| LBE | жилет, боевой подсумок, рюкзак, 2 кобуры |
| Оружие | основное оружие, боеприпасы, второе оружие, доп. боеприпасы, оружие ближнего боя |
| Броня | шлем, бронежилет, штаны, 2 слота лицевого снаряжения |
| Доп. предметы | 7 произвольных слотов |

Список доступных предметов формируется из двух источников:

1. Все категории `IMPItemChoices.xml` кроме трейтовых (`IMP_DEFAULT`,
   `IMP_RANDOMDEFAULT`, характеристики, трейтовые наборы) — базовый пул;
2. Категории выбранных трейтов (обычных и экспертных) — добавляются к пулу;
3. Записи `TableData\Inventory\IMPShopItems.xml` (необязательный файл) —
   добавляются после сборки пула с учётом привязки к набору, см.
   `docs/wiki_imp_shop_assortment.md`.

Стоимость выбранных предметов суммируется. Бесплатная часть — бюджет снаряжения
`IMP_SHOP_GEAR_BUDGET` (по умолчанию 5000$, при `0` используется `IMP_PROFILE_COST`).
Сверх бюджета стоимость **доплачивается отдельно** к цене профиля. На странице
выбора всегда показано `Снаряжение: %d / %d $   Доплата: %d $`
(`szIMPGearWebSiteText[8]`), а при доплате кнопка Finish сначала запрашивает
подтверждение с точной суммой (`szIMPGearWebSiteText[9]`).

## Поток выполнения (полная цепочка)

```
IMP Attribute Selection: кнопка Finish
  └─ iCurrentImpPage = IMP_GEAR_ENTRANCE, SetGeneratedCharacterAttributes()
IMP Gear Entrance: выбор метода
  ├─ «Автоматически» → fNewIMPGearMethodUsed = FALSE
  │    └─ iCurrentImpPage = IMP_FINISH, iCurrentProfileMode = IMP__FINISH
  └─ «Вручную» → fNewIMPGearMethodUsed = TRUE
       └─ iCurrentImpPage = IMP_GEAR
IMP Gear: выбор предметов по слотам
  └─ CalculatePossibleItems()      → пул предметов (XML + трейты)
  └─ DistributePossibleItemsOnDropDowns() → раскладка по дропдаунам
  └─ StoreSelectedIMPGear()        → gIMPGearSelectedItems (предмет → кол-во)
  └─ кнопка Finish → iCurrentImpPage = IMP_FINISH
IMP Confirm: подтверждение
  └─ GiveItemsToPC()
       ├─ IsIMPGearUsed() → GiveIMPSelectedGear(pProfile)
       │    └─ MakeProfileInvItemAnySlot() на каждый выбранный предмет
       └─ иначе стандартная выдача (+ GiveIMPRandomItems(IMP_SIDEARM))
  └─ DistributeInitialGear() — раскладка по карманам
  └─ оплата: iGetProfileCost(TRUE) = профиль + снаряжение сверх лимита
```

## Стоимость

| Функция | Назначение |
|---------|-----------|
| `GetIMPShopGearBudget()` | Бюджет снаряжения: `IMP_SHOP_GEAR_BUDGET`, а при `0` — `IMP_PROFILE_COST` |
| `GetIMPGearCost()` | Стоимость снаряжения **сверх бюджета**: `max(0, gIMPGearCost - GetIMPShopGearBudget())`, только при новом методе |
| `iGetProfileCost( aWithGearCost )` | Полная стоимость профиля. `aWithGearCost=TRUE` — при создании IMP (профиль + перерасход снаряжения), `FALSE` — при проверке баланса на главной странице IMP и при загрузке существующего профиля |
| `GetEquippedGearCost( pProfile )` | Стоимость всего инвентаря профиля (цена × количество по каждому слоту). Используется при загрузке существующего IMP — стоимость снаряжения не сохраняется в файле профиля, поэтому вычисляется по факту |

Логика оплаты при загрузке ранее созданного IMP (коммит b988df876):

```cpp
INT32 iIMPCost = iGetProfileCost( FALSE );
iIMPCost += max( 0, GetEquippedGearCost( &gMercProfiles[iProfileId] )
                  - GetIMPShopGearBudget() );
```

При динамической стоимости (`DYNAMIC_IMP_PROFILE_COST`) цена профиля
умножается на число занятых IMP-слотов, перерасход снаряжения добавляется
сверху.

## Конфигурация

### `Ja2.ini` → `[Recruitment Settings]`

| Параметр | По умолчанию | Назначение |
|----------|:---:|-----------|
| `IMP_PROFILE_COST` | 3000 | Стоимость профиля IMP (деньги) |
| `IMP_SHOP_GEAR_BUDGET` | 5000 | Бюджет снаряжения в магазине IMP; `0` — брать `IMP_PROFILE_COST` |
| `DYNAMIC_IMP_PROFILE_COST` | FALSE | Цена профиля растёт с каждым занятым IMP-слотом |

### XML

- `TableData\IMPItemChoices.xml` — категории предметов. Существующие
  категории используются как есть; новая категория `Sidearm` (uiIndex 52)
  добавлена в выдачу старого метода. Полнота категорий на совести
  мод-сборки: пустые категории просто не дают предметов в пул.
- `TableData\Inventory\IMPShopItems.xml` — необязательный файл, который
  **дополняет** ассортимент магазина: id предмета, цена, крутость, привязка
  к набору `IMPItemChoices`, лимит количества, принудительная доступность и
  исключение предмета. Отсутствие файла ничего не меняет. Подробности —
  `docs/wiki_imp_shop_assortment.md`.

### Графика

- `Interface\plusminusbuttons.sti` — кнопки +/− количества. В базовой
  поставке 7609 отсутствует, файл извлечён из upstream (r7529) и установлен
  в `Data-User\Interface\` (VFS загружает Data-User поверх SLF-архивов).
- `LAPTOP\button_2.sti` — кнопки страниц, уже есть в `LAPTOP.SLF`.

## Дополнительное снаряжение (IMPShopItems.xml)

Базовый пул магазина собирается из `IMPItemChoices.xml` по категориям и выбранным
трейтам. Файл `IMPShopItems.xml` **дополняет** его: позволяет добавить любой предмет,
задать цену, крутость, привязку к набору и лимит количества, а также убрать лишнее.
Файл необязательный: если его нет, магазин работает как раньше.

Полный справочник по формату и правилам — `docs/wiki_imp_shop_assortment.md`.

### Где лежит файл

Источник (версионируется в репозитории):

```
<repo>\GameDirectory\<папка мода>\TableData\Inventory\IMPShopItems.xml
```

При деплое содержимое `GameDirectory` копируется в папку игры, и VFS читает
**один** файл по пути `<папка игры>\<папка мода>\TableData\Inventory\IMPShopItems.xml`
— из профиля с наибольшим приоритетом:

| Конфигурация | Используемый файл |
|--------------|-------------------|
| vanilla | `Data\...` |
| 113 | `Data-1.13\...` |
| AR+SDO, SDO | `Data-SDO\...` |
| AR+AFS | `Data-AFS\...` |

В `Data-User` файла нет специально: он перекрыл бы ассортимент всех модов сразу.
Моды-архивы (`Data-AR*.7z`, `Data-WF*.7z`, `Data-SDO-ru.7z`) свой `Items.xml`
не содержат, поэтому им достаётся файл базовой папки; исключение — `Data-DL113.7z`
(у него свой `Items.xml` внутри архива).

### Настройки файла

Корневое поле:

| Поле | По умолчанию | Назначение |
|------|:---:|-----------|
| `fRespectCoolness` | 0 | `0` — крутость не ограничивает показ; `1` — предмет с заданной крутостью появляется только при прогрессе кампании `крутость × 10 %` |

Поля записи `<IMPSHOPITEM>`:

| Поле | Обяз. | Назначение |
|------|:---:|-----------|
| `uiIndex` | нет | номер записи для сообщений в лог |
| `usItem` | **да** | `uiIndex` предмета из `Items.xml` |
| `usPrice` | нет | цена в магазине IMP; `0` — взять `usPrice` из `Items.xml` |
| `ubCoolness` | нет | крутость; `0` — взять из `Items.xml`. Заданная разрешает предмет даже при нулевой крутости в `Items.xml` |
| `ubKit` | нет | `uiIndex` категории `IMPItemChoices`; `255` — доступен всем, иначе только с этим набором/трейтом |
| `ubMaxAmount` | нет | максимум копий в снаряжении; `0` — без ограничения |
| `fForceAvailable` | нет | `1` — добавить предмет, игнорируя `ItemIsLegal` (Sci-Fi, чужая система инвентаря и т.п.) |
| `fRemove` | нет | `1` — убрать предмет из ассортимента, даже если он пришёл из `IMPItemChoices.xml` |
| `szComment` | нет | произвольный текст, игрой не используется |

Пример записи:

```xml
<IMPSHOPITEM>
    <uiIndex>1</uiIndex>
    <usItem>201</usItem>
    <usPrice>0</usPrice>
    <ubCoolness>1</ubCoolness>
    <ubKit>255</ubKit>
    <ubMaxAmount>2</ubMaxAmount>
    <fForceAvailable>0</fForceAvailable>
    <fRemove>0</fRemove>
    <szComment>1st Aid Kit</szComment>
</IMPSHOPITEM>
```

### Готовые файлы по модам

| Папка | Записей | Цены, $ |
|-------|--------:|---------|
| `Data` | 35 | 50–1602 |
| `Data-1.13` | 49 | 50–1760 |
| `Data-AFS` | 43 | 50–4150 |
| `Data-SDO` | 57 | 40–1500 |

Правила подбора: крутость только 1–4 (без endgame), цена не переопределяется,
`fForceAvailable = 0`; броня, разгрузка и оружие — 1 копия, медицина и граны — 2;
специализированные вещи привязаны к трейтам (24 — Night Ops, 31 — Lockpicking,
33 — Camouflage, 51 — Vox Operator).

### Как сгенерировать файл

Нужен Python 3, сторонние библиотеки не требуются.

1. Списки предметов и правила лежат в `docs/imp_kits/generate_imp_shop.py`,
   в таблице `MODS` (мод → группы → записи).
2. Запуск из корня репозитория:

```
python docs/imp_kits/generate_imp_shop.py --game-root D:\Projects\JA2_Game
```

Скрипт читает данные из папки игры (`--game-root`), а готовые файлы пишет
в репозиторий: `--out-root`, по умолчанию `<repo>\GameDirectory`.
Дальше `GameDirectory` копируется в игру.

3. Для каждого мода скрипт:
   - читает `TableData\Items\Items.xml` и `TableData\Inventory\IMPItemChoices.xml`;
   - проверяет, что предмет существует и его крутость в диапазоне 1–4;
   - проверяет, что категория `ubKit` есть в `IMPItemChoices.xml` этого мода;
   - записывает `GameDirectory\<мод>\TableData\Inventory\IMPShopItems.xml` (UTF-8, CRLF).
4. Если проверка не прошла, файл этого мода не перезаписывается, а ошибки
   выводятся в консоль.
5. После изменения крутости или состава предметов в `Items.xml` скрипт нужно
   перезапустить; цены читаются из `Items.xml` во время игры.

Как добавить предмет: в `MODS` найти мод и группу и добавить запись `e(<id>)`.
Второй аргумент — лимит копий, третий — привязка к набору (`KIT_ALWAYS` по умолчанию).
Например: `e(201, 2)` — аптечка, не больше двух; `e(1697, 1, KIT_RADIO_OPERATOR)` —
рация только для Vox Operator.

## Новые страницы IMP (CharProfile.h)

```cpp
enum{
    ...
    IMP_BACKGROUND,
    IMP_PREJUDICE,
    IMP_GEAR_ENTRANCE,   // выбор метода снаряжения
    IMP_GEAR,            // экран ручного выбора

    IMP_NUM_PAGES,
};
```

Обе страницы подключены во всех четырёх switch'ах `CharProfile.cpp`:
`HandleCharProfile`, `RenderCharProfile`, `ExitOldIMPMode`, `EnterNewIMPMode`.
Переход на них — из `IMP Attribute Selection.cpp`
(`BtnIMPAttributeFinishCallback`), возврат — в `IMP_FINISH` (страница Finish,
как и в upstream, пропускается кнопкой Finish экрана снаряжения).

## Расширение DropDown

`DropDownBase` (`Laptop\DropDown.h/.cpp`) дополнен API, который нужен фиче
(в upstream эти методы появились в соседних фичах, в базе 7609 их не было):

| Метод | Назначение |
|-------|-----------|
| `SetNthEntry( UINT8 )` | Выбрать n-ю запись (с защитой от выхода за границы) |
| `HasEntries()` | Есть ли записи вообще |
| `ClearEntries()` | Очистить список, сбросить выбор |
| `GetX()` / `GetY()` | Координаты дропдауна (для отрисовки превью предмета левее списка) |
| `GetSelectedEntryKey()` | Безопасная версия: `-1` для пустого списка (фикс upstream) |

В `enum definedDropDowns` добавлены 22 идентификатора `DROPDOWNNR_IMPGEAR_*`
— по одному на каждый дропдаун экрана (синглтоны `DropDownTemplate<N>`).

`IMP Gear.cpp` работает с дропдаунами через массив указателей
`DropDownBase* pIMPGEARDropDown[]`, что позволяет обрабатывать их циклом.

## Хранение выбора

Выбор снаряжения живёт только в памяти (`gIMPGearSelectedItems`,
`std::map<UINT16, UINT8>`) и **не сохраняется** в файл IMP-профиля. В файл
попадают уже распределённые предметы (`gMercProfiles[].inv[]`), поэтому:

- перерасход стоимости при повторном найме/загрузке вычисляется по факту
  через `GetEquippedGearCost`;
- флаг метода (`fNewIMPGearMethodUsed`) сбрасывается при выходе с экрана
  подтверждения — это переменная создания персонажа, не профиля.

Дубликаты: один и тот же предмет в нескольких слотах учитывается один раз
(фикс upstream 200899593).

## Бюджет снаряжения в интерфейсе

На экране выбора снаряжения постоянно отображается строка вида
`Снаряжение: 2450 / 5000 $   Доплата: 0 $` (строка `szIMPGearWebSiteText[8]`).
Когда стоимость превышает бюджет, сумма доплаты выделяется красным.

Если снаряжение выходит за бюджет, кнопка Finish сначала показывает
подтверждение с точной суммой (`szIMPGearWebSiteText[9]`):

```
Снаряжение выходит за бюджет на 1000$. Итого к оплате: 4000$. Продолжить?
```

Текст автоматически переносится по ширине popup-бокса: символ `\n` в этих
сообщениях использовать нельзя — рендерер выводит его как мусорный глиф.

При отказе выбор остаётся как есть, ничего не списывается. Если на счету
не хватает денег на профиль и доплату, вместо подтверждения показывается
сообщение `pImpPopUpStrings[3]` («недостаточно денег»), и выбор также сохраняется.

## Известные ограничения

- Страница Finish после выбора снаряжения, как и в upstream, не показывается
  отдельно — она вызывается напрямую (`IMP_FINISH`), пользователь видит её
  как финальное подтверждение с полной стоимостью.
- Кол-во предметов ограничено 0–9 на слот (одна цифра в UI).
- Дропдаун показывает максимум 8 записей одновременно (`DROPDOWN_REGIONS`),
  остальные — через скроллбар (штатное поведение класса).
- Русская локализация выполнена; остальные 6 языков содержат английские
  строки с пометкой `TODO.Translate`.
- Стоимость снаряжения не сохраняется в IMP-файле — при загрузке профиля
  она вычисляется по текущим ценам `Items.xml`; изменение цен в XML меняет
  и доплату за старые профили.
- Выбор снаряжения намеренно не сохраняется в профиль: `SAVE_GAME_VERSION`
  остаётся 151, формат сейва и `.dat2` не меняется. Набор при необходимости
  восстанавливается из `inv[]` профиля.
- Кнопки +/− требуют `plusminusbuttons.sti`; без него экран выбора упадёт
  на `LoadButtonImage` (файл должен присутствовать в Data-User\Interface).
